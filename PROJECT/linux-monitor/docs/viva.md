# Viva Questions and Answers

**Q1: What is the `/proc` filesystem?**
A: It is a virtual pseudo-filesystem in Linux dynamically generated by the kernel. It does not exist on disk but acts as an interface to internal kernel data structures, providing system and process information.

**Q2: Why use `/proc/stat`?**
A: It contains cumulative CPU timing metrics (ticks) spent in various states (user, system, idle) since boot, which is necessary to calculate CPU usage.

**Q3: How is CPU usage calculated?**
A: By taking two samples of `/proc/stat` at different times. We calculate the difference in total ticks and the difference in active ticks, and the usage percentage is `(active_diff / total_diff) * 100`.

**Q4: Why do we need two CPU samples?**
A: Because `/proc/stat` gives cumulative ticks since boot. A single snapshot only tells you average usage since the computer turned on. Two samples give current usage over that interval.

**Q5: What is a process state?**
A: The current lifecycle condition of a process (e.g., 'R' for Running, 'S' for Sleeping, 'Z' for Zombie).

**Q6: What is RSS?**
A: Resident Set Size. It is the portion of a process's memory that is currently held in physical RAM (pages).

**Q7: What is virtual memory?**
A: An abstraction that gives processes the illusion of contiguous memory, mapping to physical RAM or Swap.

**Q8: Why use pthreads?**
A: To allow the application to perform multiple tasks concurrently (scanning `/proc` and responding to user keystrokes) without blocking each other.

**Q9: What is a mutex?**
A: Mutual Exclusion lock. It ensures that only one thread can access a shared resource (like our `SharedData`) at a time.

**Q10: What is a race condition?**
A: A scenario where two or more threads attempt to read and write shared data at the same time, leading to corrupted or unpredictable data.

**Q11: What is a signal?**
A: A software interrupt delivered to a process to notify it of an event or to command it to perform an action (like terminate).

**Q12: Difference between SIGTERM and SIGKILL?**
A: SIGTERM (15) asks the process to terminate gracefully, allowing cleanup. SIGKILL (9) forcefully terminates the process immediately via the kernel; it cannot be caught or ignored.

**Q13: What does the `kill()` system call do?**
A: Despite the name, it sends a specified signal to a specified process ID.

**Q14: Why use `opendir()`/`readdir()`?**
A: These are POSIX system calls to read directory contents, used to discover running processes by reading the numeric directories in `/proc`.

**Q15: What are system calls?**
A: The programmatic interface for an application to request services from the operating system kernel (e.g., file I/O, process creation).

**Q16: Why use ncurses?**
A: It is a C library that provides an API for text-based user interfaces, allowing us to draw tables and text at specific coordinates in the terminal without scrolling the screen.

**Q17: Why is the application lightweight?**
A: It reads directly from memory-mapped kernel variables in `/proc` via standard file I/O instead of spawning external shell processes (like `system("ps")`), and uses a compiled language (C++) with no heavy runtime.

**Q18: What is `sysinfo()`?**
A: A Linux-specific system call that returns overall system statistics like uptime, load averages, and memory space.

**Q19: How do you handle a process disappearing during a scan?**
A: Processes die continuously. We handle this by checking if `std::ifstream` successfully opens `/proc/[pid]/stat`. If it fails, we simply `continue` and ignore the dead process.

**Q20: Why do we check permissions before sending a signal?**
A: Only the root user or the owner of a process can send signals to it. We check the return value of `kill()` and use `errno` (EPERM) to inform the user.
